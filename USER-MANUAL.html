1. What this is

Online form for The LaSalle Chicago wedding room-block logistics. No server you run.

  • Password gate (guest or staff code)
  • Save progress / resume later
  • Answers in SharePoint list Wedding Room Planner
  • Guest save → resume email; guest submit → staff PDF email
  • Staff edits stay quiet (list / PDF only)

3. Use the form — couples

Give them: (1) the form link, (2) the guest access code.

  1. Open the link in Chrome, Edge, or Safari.
  2. Enter the guest access code → Unlock.
  3. Fill contact (couple/party name, wedding date, email), then the rest.
  4. Save progress anytime — resume email. Not final yet.
  5. Submit final when complete — hotel gets the PDF.
Done when
  • Before Save: name, wedding date, email
  • Before Submit: full form (No on valet/bags/brunch/ready-room skips those details)

4. Use the form — staff

Use the staff code. You should see a gold Staff mode banner after unlock.

  1. Unlock with the staff code.
  2. Enter couple name + wedding date (minimum).
  3. Save progress — no customer email on staff save.
  4. Copy Form URL (address bar or list) → send link + guest code.
  5. Review later: List → Form URL → staff code → edit → Save. After guest submit, staff re-submit refreshes PDF without another email.
Staff-only block “Important dates at a glance” uses data-staff-only in index.html (about lines 427–432). Hidden for guests.

7. Passwords and API URL

Codes live in Power Automate. API_URL is public on purpose (browser needs it).

  1. Open make.powerautomate.com → Wedding Room Block Form - API → Edit.
  2. Edit Compose FormPassword (guest) or StaffPassword (staff).
  3. Save → keep flow On → test unlock.
ItemPublic?Where
Guest / staff codesNoPower Automate Compose only
API_URLYesconfig.js lines 14–17 (FORM_CONFIG.API_URL). Rotate if leaked/spam.
Do not put live codes in GitHub MOCK_PASSWORD / MOCK_STAFF_PASSWORD in config.js (lines 8–12) are for MOCK_MODE: true only.

9. Add or change a field

Contract first: type + JSON key → list → Power Automate → HTML → dry-run → then push. A list column with no app.js key stays empty.

Code map (GitHub repo)

Repo root: https://github.com/TheLasalleChicago-hydai/wedding-room-block-form. Line numbers are from the current tree — if they drift, search the function name.

WhatFileBlock / lines

Date keys app.js collectPayload() → payload = { dateIsoOf… } — lines 709–720

Rare exception Staff-only list column filled by hand (no form, no flow map) is OK. Anything couples type needs the full chain.
  1. Backup before edits
    • Git: create a branch, or download a ZIP of the repo. Local Excel/flow copies can go in the ignored backups/ folder.
    • Power Automate: ⋯ on the flow → Save as (keep a working copy).
    • SharePoint list: open Wedding Room Planner → Export → Export to Excel (or CSV). Save dated copy under backups/.
  2. Choose type + machine name

    Name: lowercase + underscores only (example guest_rooms_notes). Same string in HTML, app.js, and PA.

    NeedSharePoint typeWhere in app.js
    Short textSingle line of textfields array (666–707)
    Long notesMultiple lines of textfields array
    Whole numberNumberfields + step 4.5 if optional
    Calendar dateDate onlydateIsoOf block (709–720) + step 4.5
    Yes / NoChoice yes/nofields; never int() in PA
  3. Edit app.js — JSON payload
    • Open app.js → collectPayload() (starts ~line 666).
    • Text / number / time / yes-no: add the machine name inside the fields array (lines 667–707).
    • Dates: add your_field: dateIsoOf("your_field"), in the payload = { … } object (lines 709–720).
    • Staff-only UI: wrap HTML later with data-staff-only. Visibility is toggled in applyStaffUi() (lines 861–866).
    Skip this → blank forever HTML alone does not send data.
  4. Create the SharePoint column
    • Lists → Wedding Room Planner → + Add column → type from the table → Save.
    • Rename: Column settings → Edit, then re-check Create/Update in the flow (step 4).
  5. Map in Power Automate
    • Edit Wedding Room Block Form - API.
    • Every Create item + Update item on saveDraft and submitFinal.
    • Expression: json(triggerBody())?['payload']?['guest_rooms_notes']
    • Document in power-automate/FIELD-MAP.md (top mapping table).
    • PDF: add a box in Compose SubmitHTML / DraftHTML; templates in power-automate/FORM-PDF-HTML.md.
  6. Null-safe expression (if blank on draft Save can break SharePoint) 
    if(empty(json(triggerBody())?['payload']?['group_arrival']), null, json(triggerBody())?['payload']?['group_arrival'])
    if(empty(json(triggerBody())?['payload']?['valet_vehicles']), null, int(json(triggerBody())?['payload']?['valet_vehicles']))
    if(empty(json(triggerBody())?['payload']?['valet_needed']), null, json(triggerBody())?['payload']?['valet_needed'])

    Choices are text — do not wrap with int().

  7. Verify mapping
    • Column appears on Create/Update after refresh.
    • Optional: Flow Test with a body that includes your payload key.
    • After HTML exists: Run history → Create/Update shows the value.
  8. Add HTML — index.html
    • Open index.html. Sections start ~line 95. Paste next to similar fields (e.g. Rooms & VIP ~line 187).
    • id, name, data-field, and data-error-for must match the machine name from step 1.
    <div class="field" data-field="guest_rooms_notes">
  <label for="guest_rooms_notes">Guest room notes</label>
  <input id="guest_rooms_notes" name="guest_rooms_notes" type="text" />
  <div class="field-error" data-error-for="guest_rooms_notes"></div>
</div>
    LayoutHow
    New section<section class="section"> + <h2> + field-grid or field-grid two
    Datetype="date" + data-date-field
    Yes/NoTwo radios, same name, values yes / no
    Staff onlyAdd data-staff-only (see lines 427–432)
  9. Layout check
    • Local: npx --yes serve . — use config.js MOCK_MODE (line 8) for UI-only.
    • Hard-refresh (Ctrl+Shift+R) after JS/HTML edits.
  10. Full dry-run, then commit / push
    • Staff unlock → fill the new field → Save → confirm SharePoint cell.
    • Submit → confirm PDF if you added it.
    • Only then commit/push index.html, app.js, FIELD-MAP.md as needed to main.
Done when
  • Key in collectPayload() (app.js ~666+)
  • List column fills after Save
  • Create+Update mapped on save and submit
  • HTML visible; dry-run passed before push

Wording / look only

  1. Edit labels in index.html (~95+), styles in styles.css, or intro in config.js (lines 19–23).
  2. Preview → push. Skip list/PA if no new data.

Rename a column

  1. List → Column settings → Edit display name.
  2. PA → confirm Create/Update still mapped.
  3. Update form/PDF label if needed. Machine name in app.js can stay.
  4. Update FIELD-MAP.md → dry-run Save.

Stop collecting a field

  1. Remove HTML in index.html; remove key from collectPayload() (app.js 666–720).
  2. Clear PA mappings; remove PDF line.
  3. Hide list column from view first.
  4. Dry-run → push.

10. Change notification emails

Guest submit emails the hotel. Staff save/submit stay silent.

  1. Power Automate → Wedding Room Block Form - API → Edit.
  2. Find Send an email (V2) on the guest submit path.
  3. Set To / Cc (prefer a shared mailbox).
  4. Save → guest-submit dry-run → confirm inbox.

11. Troubleshoot

  1. Flow → Run history → open the run for your Save time.
  2. Red X = failed step. Skipped Response 200 often causes form “upstream” errors.
