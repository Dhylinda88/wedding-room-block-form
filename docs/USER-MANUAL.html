1. What this is

Online form for The LaSalle Chicago wedding room-block logistics. No server you run.

  • Password gate (guest code or staff code)
  • Save progress / resume later
  • Answers stored in SharePoint list Wedding Room Planner
  • Guest save → resume email; guest submit → staff PDF email
  • Staff edits stay quiet (list/PDF only)

3. Couples: use the form

Give them: (1) the form link, (2) the guest access code.

  1. Open the link in Chrome, Edge, or Safari.
  2. Enter the guest access code → Unlock.
  3. Fill contact (couple/party name, wedding date, email) then the rest.
  4. Save progress anytime — they get a resume email. Not final yet.
  5. Submit final when complete — thank-you screen; hotel gets the PDF.
Done when
  • Before Save: name, wedding date, email filled
  • Before Submit: full form (No on valet/bags/brunch/ready-room skips those details)

4. Staff: use the form

Use the staff code. After unlock you should see a gold Staff mode banner.

  1. Unlock with the staff code.
  2. Enter couple name + wedding date (minimum).
  3. Save progress — no customer email on staff save.
  4. Copy Form URL from the address bar or the SharePoint list → send link + guest code to the couple.
  5. Review later: List → Form URL → staff code → edit → Save. After guest submit, staff re-submit refreshes PDF without another email.
Staff-only block “Important dates at a glance” is hidden from guests (data-staff-only).

7. Passwords & API URL

Guest/staff codes live in Power Automate only. The public API_URL is required for the form to talk to the flow.

Change a code

  1. Open make.powerautomate.com → Wedding Room Block Form - API → Edit.
  2. Edit Compose FormPassword (guest) or StaffPassword (staff).
  3. Save → keep flow On → test unlock on the live form.
SecretPublic?Notes
Guest / staff codesNoPower Automate Compose only
API_URL in config.jsYesNeeded by the browser. Includes a sig= token. Anyone with the URL can call the flow; unlock still needs a code. Rotate if leaked/spam.

Rotate API URL

  1. Copy new HTTP POST URL from the flow trigger.
  2. Paste into config.js → API_URL.
  3. Commit/push → hard-refresh form → test unlock.
Never put live codes in GitHub MOCK_PASSWORD / MOCK_STAFF_PASSWORD are for MOCK_MODE: true only.

9. HOW-TO: Add or change a field

Contract first: type + JSON key → list → Power Automate → HTML → dry-run → then push. A list column with no app.js key stays empty forever.

Rare exception A staff-only list column filled by hand (no form, no flow map) is allowed. Everything couples type needs the full chain.
  1. BACKUP before edits
    • Git: create a branch, or download a ZIP of the repo.
    • Power Automate: ⋯ on the flow → Save as (keep a copy before changing Create/Update).
  2. Choose data type + machine name

    Machine name: lowercase + underscores only (example guest_rooms_notes). Same string everywhere.

    Form needSharePoint typePayload tip
    Short textSingle line of textAdd to fields array in collectPayload()
    Long notesMultiple lines of textSame
    Whole numberNumberSame + null-safe if optional (4.5)
    Calendar dateDate and time (Date only)Use dateIsoOf("name") + null-safe (4.5)
    Yes / NoChoice (yes / no)Radios; never int() in PA
  3. Edit app.js (JSON payload)
    1. Open app.js → function collectPayload().
    2. Text / number / time / yes-no: add the machine name to the fields array.
    3. Dates: also add your_field: dateIsoOf("your_field"), in the payload = { … } object.
    4. Staff-only UI: wrap the HTML later in data-staff-only (step 6). applyStaffUi() already hides those until staff unlock.
    5. Optional required: add validation in the same file’s error object (pattern like couple_name).
    Skip this → blank forever HTML alone does not send data. Power Automate cannot invent a missing payload key.
  4. Create the SharePoint column
    1. Microsoft Lists → Wedding Room Planner.
    2. + Add column → type from the table above → clear display name → Save.
    3. Rename later: Column settings → Edit. Then re-check Create/Update in the flow (step 4).
  5. Map the column in Power Automate
    1. Edit flow Wedding Room Block Form - API.
    2. Update every Create item + Update item for this list on saveDraft and submitFinal (often four places).
    3. If the column is missing: Show all / refresh, or re-add the action.
    4. Expression (replace name): 
      json(triggerBody())?['payload']?['guest_rooms_notes']
    5. Save the flow. Leave it On.
    6. Document the row in power-automate/FIELD-MAP.md.
    7. PDF: if staff need it on the PDF, add a box in Compose SubmitHTML / DraftHTML (same payload path). Template: power-automate/FORM-PDF-HTML.md.
  6. Null-safe expression (if the field can be blank on draft Save)

    Empty date/number sent as "" often fails SharePoint. Paste Expression (not text):

    Date example:

    if(empty(json(triggerBody())?['payload']?['group_arrival']), null, json(triggerBody())?['payload']?['group_arrival'])

    Number example:

    if(empty(json(triggerBody())?['payload']?['valet_vehicles']), null, int(json(triggerBody())?['payload']?['valet_vehicles']))

    Choice (yes/no) — text only, no int():

    if(empty(json(triggerBody())?['payload']?['valet_needed']), null, json(triggerBody())?['payload']?['valet_needed'])
  7. Verify mapping
    1. Confirm the new column appears on Create/Update after refresh.
    2. Optional: Flow Test with a sample body that includes your payload key.
    3. After HTML exists (step 6+), confirm run history Create/Update shows the value (no red error).
  8. Add HTML (index.html)

    Copy a same-type field block. Machine name must match step 1–2.

    <div class="field" data-field="guest_rooms_notes">
  <label for="guest_rooms_notes">Guest room notes</label>
  <input id="guest_rooms_notes" name="guest_rooms_notes" type="text" />
  <div class="field-error" data-error-for="guest_rooms_notes"></div>
</div>
    LayoutHow
    New section<section class="section"> + <h2> + field-grid or field-grid two
    Two columnsParent class="field-grid two"
    Datetype="date" + data-date-field
    Yes/NoTwo radios, same name, values yes / no
    Staff onlyWrap block with data-staff-only (hidden for guests)
  9. Check layout
    1. Local: npx --yes serve . with MOCK_MODE: true for UI-only, or false + live API_URL to hit the real flow.
    2. Confirm label, spacing, conditionals look right. Hard-refresh (Ctrl+Shift+R) after JS/HTML edits.
  10. Full dry-run (required before push)
    1. Staff unlock → fill the new field with a known test value.
    2. Save progress → open SharePoint row → value present.
    3. Submit final → status submitted; PDF shows the field (if you added it).
    4. Optional: guest path once (save email + submit email) if the field is customer-facing.
    5. Only then commit/push index.html, app.js, FIELD-MAP, manual as needed to main.
Done when
  • Payload key in collectPayload()
  • List column filled after Save
  • Create+Update mapped on save + submit
  • HTML visible (and staff-only rules work)
  • Dry-run passed before push

Wording / look only (no new data)

  1. Edit labels in index.html or styles in styles.css / intro in config.js.
  2. Preview → push. Skip list/PA if nothing new is collected.

Rename a column

  1. List → Column settings → Edit display name.
  2. PA → confirm Create/Update still show the field.
  3. Update form/PDF label if customers see it. Machine name in app.js can stay.
  4. Update FIELD-MAP → dry-run Save.

Stop collecting a field

  1. Remove HTML + remove from collectPayload().
  2. Clear PA mappings; remove PDF line.
  3. Hide list column from view first (delete later if safe).
  4. Dry-run → push.

10. HOW-TO: Change notification emails

Guest submit emails the hotel. Staff save/submit stay silent on purpose.

  1. Power Automate → Wedding Room Block Form - API → Edit.
  2. Find Send an email (V2) on the guest submit path (after PDF).
  3. Set To / Cc (prefer a shared mailbox so you don’t edit the flow for every hire).
  4. Save → guest-submit dry-run → confirm inbox.
Done when
  • A guest Submit lands in the intended mailbox with PDF.

11. Troubleshoot

Form error or blank column → Run history first.

  1. Power Automate → flow → Run history → open the run that matches your Save time.
  2. Red X = failed step (read the error). Skipped Response 200 = form often shows “upstream” even if later steps worked.
